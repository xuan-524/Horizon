## [Transformers v5.17.0 新增 780B 混合专家模型 HYV4，支持 100 万 token 上下文](https://github.com/huggingface/transformers/releases/tag/v5.17.0) ⭐️ 8.0/10

Hugging Face 发布 Transformers v5.17.0，新增对 HYV4-Preview 的支持：这是一个 780B 参数的混合专家语言模型，每个 token 激活 49B 参数，上下文窗口达到 100 万 token。同一版本还集成了用于长篇多说话人语音合成的 VibeVoice、用于多语言多模态编码与视觉文档检索的 NeoMME 与 NeoMME-Retriever，以及阿里达摩院 800M 参数的 Fun-ASR-Nano 语音识别模型。 Transformers 是开源 AI 生态中事实上的默认模型库，因此加入 780B 参数的 MoE 权重意味着开发者只需一次版本升级，就能加载、微调并部署前沿规模的大模型，而无需自行编写建模代码。这也说明 DeepSeek 式的效率技术——潜在注意力压缩、可学习稀疏注意力与 indexer 共享——正随着模型迈向百万级上下文而迅速融入主流工具链。 该架构融合了四项特性：Multi-head Latent Attention 通过 kv\_lora\_rank 将键和值压缩为低秩潜在表示，再由 kv\_b\_proj 还原为每个查询头对应的键值；DeepSeek Sparse Attention 用轻量级 indexer 为每个查询挑选 index\_topk 个键，且只有 indexer\_types 中标记为 &quot;full&quot; 的层才运行 indexer，&quot;shared&quot; 层则复用上一个 full 层的选择结果；带可学习 attention sink 的门控 MLA，以及用 hc\_mult 条并行残差流替换普通残差路径、并在每个子层前后折叠与重分配的独立超连接（iHC）。每个 MoE 层包含 256 个路由专家外加一个始终激活的共享专家，每个 token 路由到其中 8 个；多 token 预测（MTP）层在实现中并不执行，但发布的权重仍保留它们，以便其他运行时用于投机解码。

github · vasqu · 9月9日 15:42

**背景**: 混合专家（MoE）模型把 Transformer 的前馈部分拆成许多专用的“专家”子网络，每个 token 只激活其中少数几个，因此总参数量可以做得极大而单 token 计算量保持在中等水平——这正是 HYV4 总参数 780B、激活参数仅 49B 的原因。随 DeepSeek-V2 提出的 Multi-head Latent Attention（MLA）通过缓存压缩后的低秩潜在表示而非完整的键和值来缩小 KV cache，这对服务超长上下文至关重要。DeepSeek Sparse Attention（DSA）等稀疏注意力机制则用一个轻量级 indexer 只挑选 top-k 相关的键，避免让每个查询与所有历史 token 逐一比较；IndexShare 进一步让多个层共享同一个 indexer 的选择结果，从而在百万级上下文长度下降低单 token 的浮点运算量。

## [vLLM v0.29.0 发布：Model Runner V2 成为所有模型的默认执行路径](https://github.com/vllm-project/vllm/releases/tag/v0.29.0) ⭐️ 8.0/10

vLLM v0.29.0 包含来自 277 位贡献者（其中 91 位是新人）的 594 个提交，并完成了 Model Runner V2 的推广：在先前已用于 pooling 模型之后，如今它已成为所有模型的默认执行路径。该版本还新增了 Hy4-preview（腾讯 770B 总参数、49B 激活参数的 MoE）、Qwen3.8-Flash-Next、GraniteSWA/GraniteMoeSWA 以及 Kimi K3 NVFP4 检查点等新架构，并引入用于 KV cache 自动定容的 CUDA graph 内存分析，以及可将每步 logits 显存降低 1/TP 的 batch-sharded sampling。 vLLM 是目前部署最广泛的开源大模型推理与服务引擎之一，将默认执行核心切换为 MRV2 会直接影响大量生产部署的性能、显存行为与吞吐，而不仅仅是基准测试结果。此次迁移还带来若干破坏性变更——移除十个已弃用的模型架构、将 Olmo3/FlexOlmo/Hunyuan V1 迁移到 Transformers 建模后端、删除 PyAV 视频解码后端——因此运维人员升级前需先评估兼容性。 MRV1 仍然保留给少数 ROCm 模型以及 MRV2 尚未支持的功能，因此这一切换并非绝对全面。该版本还变更了若干默认行为，包括为 TP CUDA 组默认启用 FlashInfer all-reduce（可通过 VLLM\_ALLREDUCE\_USE\_FLASHINFER=0 关闭）、prefix-cache 的 NONE\_HASH 默认变为确定性从而让分布式 KV cache 用户不再需要固定 PYTHONHASHSEED，以及新增 --max-num-queued-reqs/--max-num-queued-tokens 准入控制参数。

github · khluu · 9月9日 08:54

**背景**: vLLM 是一个用于大语言模型推理服务的开源引擎，以 PagedAttention 和连续批处理著称，许多团队用它来在兼容 OpenAI 的 API 后面运行模型。所谓“model runner”是把一次调度步骤转化为 GPU 工作的执行核心，负责准备输入、执行模型前向计算并采样下一个 token。Model Runner V2（MRV2）是对该核心的从零重写，目标是更简洁、更模块化：用 GPU 原生的 Triton kernel 取代大量 Python 侧开销，并将 CPU 调度与 GPU 执行解耦；在此次发布之前它已先用于 pooling 模型，本版本才扩展到所有模型。CUDA graph 是一种 GPU 技术，它把一串 kernel 调用录制一次后反复回放以降低启动开销，这正是 CUDA graph 内存分析对正确设定 KV cache 大小很重要的原因。

IEEE Spectrum 发表的《Are Self-Driving Cars Safe?》一文提出，自动驾驶汽车已经在挽救生命，并引用了 Waymo 等运营方的安全数据作为依据。这篇文章在 Hacker News 上引发了大规模讨论（201 个赞、377 条评论），讨论焦点集中在安全对比的口径设定以及需要何种证据才能获得公众认可。 自动驾驶汽车安全性的衡量方式直接影响监管政策、保险定价，以及乘客与行人是否愿意大规模接受无人驾驶汽车。如果对比基准是普通驾驶者而非清醒谨慎的驾驶者，该行业要么会高估自身收益，要么会遭到持怀疑态度的公众抵制。 评论者指出，致死事故数据受到酒驾、超速和未系安全带等因素的严重扭曲，而且美国道路死亡人数中约五分之一是行人和骑行者而非车内乘员。还有人指出，Waymo 是将自身事故率与普通驾驶者对比，而非与其实际取代的网约车司机对比，这让数据显得更好看；同时加州的路测脱离报告仍是最常被引用但并不完美的可靠性指标。

hackernews · bookofjoe · 9月9日 17:14 · [社区讨论](https://news.ycombinator.com/item?id=49629886)

**背景**: 自动驾驶能力由 SAE J3016 标准划分为六个等级，从 Level 0（无自动化）到 Level 5（任何条件下完全自动化），目前多数已部署的自动驾驶出租车服务在限定区域内以 Level 4 运营。在加州测试的公司必须每年提交路测脱离报告，记录每一次需要人类接管的情况，这些报告已成为公众判断自动驾驶可靠性的主要依据。由于完全自动驾驶里程在总行驶里程中占比仍然很小，将自动驾驶事故率与人类基准对比时，必须对行驶暴露量、地理区域和驾驶条件进行仔细归一化处理。

## [GPT-6 Astra、循环 Transformer 与隐式推理深度解析](https://magazine.sebastianraschka.com/p/gpt-6-astra-looped-transformers-and) ⭐️ 8.0/10

Sebastian Raschka 发布了一篇技术分析文章，探讨了 GPT-6 Astra 的相关猜测、循环（recurrent-depth）Transformer 架构以及“隐式推理”（hidden reasoning）的概念。文章回应了《The Information》近期的一篇报道，该报道将 Astra 使用的“循环深度”或“循环 Transformer”描述为一种会加大思维链监控难度的“秘密技术”。 文章通过阐明循环本质上是权重复用而非神秘的新机制，反驳了关于“无法监控的 AI 推理”这一危言耸听的说法，帮助从业者理解架构中真正改变的是什么。这对于关注 AI 安全、可解释性以及前沿模型推理算力如何分配的读者具有重要意义。 循环 Transformer 在解码前多次应用同一组层，其功能类似于堆叠更多层，但通过权重复用节省了 GPU 显存；诸如《Looped Transformers are Better at Learning Learning Algorithms》等相关研究表明，这类架构能够模拟迭代式和算法式计算。文章还指出，这种循环结构本身并不会隐藏模型的推理轨迹，因为中间输出原则上仍可被提取出来。

hackernews · ModelForge · 9月9日 14:37 · [社区讨论](https://news.ycombinator.com/item?id=49627370)

**背景**: Transformer 是大多数现代大语言模型所基于的神经网络架构，其“深度”指的是模型包含多少层。循环（或循环深度）Transformer 会迭代地复用一组固定的层，这一概念与早期关于 Universal Transformer 的研究以及“在推理阶段为模型提供额外‘思考’算力”的思路相关。思维链（chain-of-thought）推理指模型在给出答案前先写出中间步骤，目前学界仍在研究这些推理究竟有多少被真实表达出来、有多少是在内部执行并被隐藏的。

## [IBM 发布商用友好许可的 Granite Time Series PatchTST-FM-r2 模型](https://huggingface.co/blog/ibm-research/ibm-releases-sota-granite-time-series) ⭐️ 8.0/10

IBM Research 在 Hugging Face 上发布了 Granite Time Series PatchTST-FM-r2，并将其定位为一款采用商用友好许可的当前最优（SOTA）时间序列基础模型。此次发布让 IBM 第二代基于 patch 的 Transformer 预测模型可以直接用于商业产品，而不再受制于研究模型常见的许可限制。 时间序列预测支撑着需求规划、产能管理、电力负荷预测和金融风控等场景，因此一个真正有竞争力且商用条款宽松的开源基础模型，能显著降低那些无法使用仅限研究用途模型的企业门槛。这也会加大其他时间序列基础模型项目的竞争压力，如今这一领域的比拼已不止于架构，还包括许可条款和基准排名。 从命名可以看出该模型采用 PatchTST 风格的架构，即把时间序列切分成多个 patch（片段），由 Transformer 将它们当作 token 处理，而“-r2”后缀表明这是 Granite 时间序列家族的第二版迭代。作为基础模型，它在大规模、多样化的真实时间序列语料上预训练，因此只需少量甚至无需任务专属训练数据即可迁移到新领域。

rss · Hugging Face Blog · 9月9日 15:36

**背景**: 传统预测模型（如 ARIMA）通常需要针对每个数据集单独拟合，而时间序列基础模型则先在大量不同序列上一次性预训练，再广泛迁移应用，思路类似于大语言模型跨文本任务的泛化能力。2023 年论文《A Time Series is Worth 64 Words》提出的 PatchTST，通过把序列切分为 patch 而不是把每个时间点都送入 Transformer，改善了长周期预测效果，同时加快训练速度并延长可用输入窗口。IBM 的 Granite 是其公开发布的基础模型系列，此次发布把这一品牌延伸到时间序列领域，与 Google 的 TimesFM 等同类工作形成对照。

## [Calif Research 声称造出首个经微信通话传播的零点击蠕虫，AI 协助完成](https://simonwillison.net/2026/Sep/10/calif-research/) ⭐️ 7.0/10

Calif Research 发布了一个名为 WeWorm 的演示，声称这是首个通过微信通话在 iOS 和 Android 上传播的零点击蠕虫——受害者既不需要接听电话，也不需要任何手机操作。该团队表示，借助 AI，他们在大约两天内定位了漏洞并写出了首个远程代码执行（RCE）利用程序，随后又用一周时间构建出完整的蠕虫。 如果得到证实，这一说法意味着 AI 加速的攻防格局发生范式转变：过去这种规模的蠕虫需要一个更大的团队耗时数月才能完成，而微信庞大的用户基数意味着单次通话理论上就能劫持账号并在数小时内扩散至数百万人。它还带来关于负责任披露、补丁周期以及当漏洞利用开发被压缩到几天时防守方如何应对的严峻问题。 被引用的内容只是一段简短的引文，没有技术细节、没有 CVE 编号、没有受影响版本信息，也没有任何独立验证，而且 Calif Research 并非广为人知的安全机构，因此这些说法应被视为未经证实。其描述的行为是：即使受害者接听了通话，利用仍然成功，只是听不到任何声音——这是典型的静默、无需交互的利用链特征，而非依赖社工诱骗的手法。

rss · Simon Willison · 9月10日 00:56

**背景**: 零点击漏洞利用是指无需用户任何操作即可攻陷设备的攻击，因此比需要点击链接或打开文件的攻击危险得多；蠕虫则是能在设备之间自动自我复制的恶意软件，零点击蠕虫把这两种特性结合在一起。远程代码执行（RCE）是一类允许攻击者从远程位置在目标机器上运行任意代码的漏洞，通常是此类攻击活动中最难的一环。此前的 “Morris II” 研究论文表明，在生成式 AI 生态中零点击、自我复制的攻击是可行的；AirBorne 等项目也展示了 Apple AirPlay 中可蠕虫化的零点击 RCE，因此微信这一说法契合了更大的趋势，其独特之处在于瞄准的是消费级规模的实时语音通话通道。
